//=============================================================================
// Valkyrie Quest - MERGED SINGLE NPC VERSION (FIXED)
//=============================================================================
// All 8 original NPCs (Valkyrie, Valkyrie Amor, Radgrid, Alvitr, Vali, Asgard,
// Lydia, Bryan/Sleipnir) have been merged into ONE clickable NPC.
// The NPC "role-plays" each character in sequence as the player progresses
// through the quest chain.
//
// Quest progression is tracked with the SAME variables as the original
// scripts, so existing player save data is not broken:
//   ron_ron -> Seal broken (Valkyrie Armor unlocked)
//   kim_kim -> Armor obtained (Manteau unlocked)
//   jhe_jhe -> Manteau obtained (Shoes unlocked)
//   alv_alv -> Shoes obtained (Shield unlocked)
//   jmk_jmk -> Shield obtained (Bunch of Carnation unlocked)
//   asg_asg -> BOTH Bunch of Carnation deliveries complete (Sleipnir unlocked)
//   bry_bry -> Sleipnir obtained (quest fully complete / Mega-Warrior)
//
// NOTE ON fra_fra: the standalone "Lydia - Bunch of Carnation" stage has
// been merged into the Asgard stage (Asgard now crafts the Bunch of
// Carnation directly, using the correct item ID 2646, instead of a
// separate "Nile Rose" placeholder item). The fra_fra variable and the
// Lydia NPC dialogue are no longer used.
//
// NOTE ON hen_hen: the original 'Valkyrie' script checked a variable
// 'hen_hen' that was never actually set anywhere in the quest chain (a
// leftover/dead check). It has been dropped here in favor of 'ron_ron',
// which correctly reflects "has the seal been broken yet".
//
// FIXES APPLIED (vs original):
//   1) setdialogsize(...) crashed the client because in Stage 0 it was
//      called AFTER other mes lines had already been shown on the same
//      page (mes "These are what I need:"; setdialogsize(...); mes item;).
//      Resizing a page that has already started rendering content
//      crashes the client. Fixed by always calling setdialogsize as the
//      very FIRST line right after next; (before any mes on that page),
//      and resetting it to (0,0) on its own next; immediately after the
//      item list so it doesn't leak into later pages. All other stages
//      already followed this pattern correctly, which is why only
//      Stage 0 crashed.
//   2) The loot roll in Stage 0 (.@gamble1 1-500) had a gap at exactly
//      401 that matched no branch, leaving .@item at 0 and causing
//      getitem .@item,1; to hand out item ID 0. Range fixed so every
//      value 1-500 is covered, plus a safety fallback.
//   3) ICON UPDATE: each stage's reward hand-off message now also shows
//      the item icon sprite for the piece just received (via
//      mesitemicon()), matching the way the material requirement lists
//      already showed icons. No dialogsize calls were touched, and no
//      existing lines were removed/reordered, so this cannot reintroduce
//      the Stage 0 crash bug.
//   4) ICON PLACEMENT FIX: on each character's introductory "I craft
//      this item" line, mesitemicon() was glued to the front of the
//      whole sentence (icon, then "I am X, the Crafter of the Item").
//      Moved so the icon sits directly in front of the item name
//      instead, e.g. "I am the crafter of [icon] Item Name".
//   5) ASGARD / BUNCH OF CARNATION REWORK: replaced the old "[1/2]" /
//      "[2/2]" placeholder-item combine mechanic with two independent,
//      full Bunch of Carnation (2646) turn-ins. Each delivery hands the
//      player a real Bunch of Carnation on the spot -- no placeholder
//      items, no combine step. Progress between the two deliveries is
//      tracked by countitem(2646) (0 -> first delivery pending, 1 ->
//      second delivery pending, 2 -> both done), and asg_asg is only
//      set to 1 once the second delivery is turned in, which is what
//      unlocks Bryan/Sleipnir.
//   6) OVERWEIGHT SAFETY: every reward hand-off is now gated behind a
//      checkweight(itemid,1) check performed BEFORE any delitem/Zeny
//      deduction. If the player can't carry the reward item, nothing is
//      taken from them -- they get a "you're carrying too much" message
//      and can simply come back once they've freed up weight, with all
//      of their turn-in materials and zeny intact. In Stage 0 the random
//      reward item is now rolled up front (before materials are touched)
//      specifically so it can be weight-checked ahead of the delitem
//      call; the "Your Welcome" select is kept purely for flavor and no
//      longer drives any branching logic.
//=============================================================================
